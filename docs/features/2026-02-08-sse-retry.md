# SSE Auto-Reconnect and Polling Fallback

## Background

SSE can enter an error state during network turbulence or proxy disconnects. The client should close the broken connection and keep retrying so output streaming does not stall.

## Scope

- Close the current SSE connection inside `source.onerror`.
- Add exponential backoff for reconnection attempts.
- Keep polling as a continuous fallback to ensure output is still fetched while disconnected.

## Key Decisions

- Use exponential backoff starting at 1s with a 30s cap; reset on `onopen`.
- Clear `sseRef` after closing to avoid treating a dead connection as open.
- Keep polling independent from SSE so either path can deliver updates.

## Validation

- Manual: disconnect network for 10–20 seconds, then restore and confirm output resumes and SSE reconnects.
- Automated:

```bash
cd web
npm test
```

## Follow-ups

- Observe long offline periods and adjust the backoff cap if needed.
