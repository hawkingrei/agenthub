## Summary

- suppress the known benign `codex_core::codex` rollout shutdown log in `agenthub-codex-acp`
- keep unrelated Codex error logs visible by matching only the closed-channel rollout message prefix
- document the shutdown-noise rationale and add a post-merge verification item

## Why

AgentHub-managed Codex ACP sessions can emit this during normal shutdown:

```text
failed to record rollout items: failed to queue rollout items: channel closed
```

The underlying `codex-core` behavior is a shutdown race around the rollout writer channel. In AgentHub this is normal shutdown noise rather than a user-actionable ACP failure, so surfacing it as an adapter `ERROR` is misleading.

## Notes

- This PR does not patch upstream `codex-core`; it applies a narrow adapter-side suppression for the known benign log line.
- Follow-up merge verification is tracked in `docs/todo.md`.
